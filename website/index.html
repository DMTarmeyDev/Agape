What Agape is for

One workspace for AI-assisted project work.

Agape is designed to reduce the amount of model-juggling, terminal-watching and technical decision-making the user has to do manually.

✦

Automatic model routing

Route work to the most appropriate available AI model or provider instead of locking the whole application to a single model.

↻

Safe automation loops

Run iterative project workflows with validation gates, visible progress, checkpoints and a path back when a change fails.

✓

Test before trust

Make testing part of the workflow so generated code and project changes can be checked instead of simply accepted.

▤

Documents & outputs

Develop structured documents and other deliverables from a brief, while keeping supporting work and project context together.

⌘

Developer power when needed

Expose projects, development controls, terminal history, models and diagnostics for advanced users without forcing them onto everyone.

◉

Local-first control

Keep a local application core and project data while still allowing optional online models, research and external connectors.

Architecture

Simple on the surface. Structured underneath.

The interface is intended to speak in tasks and outcomes. Technical systems become progressively visible only when they are useful.

01

Human-first UI

Create, ask, review progress and open completed work without needing to understand the orchestration engine.

02

Project orchestration

Break work into stages, track state, close completed sections and keep failed work visible for repair.

03

Model & tool routing

Select from available local and online models and tools according to the job instead of using a fixed provider.

04

Validation, data & recovery

Tests, checkpoints, project records and rollback mechanisms provide a safer foundation for automation.

Early Alpha

Agape is under active development. Interfaces, installers and internal modules can change, and some workflows may still be incomplete or experimental. Use test data and keep backups while evaluating it.

Current direction

Windows-first today, broader platform support in view.

The project has a browser-based core and has been developed toward a native Windows desktop experience. The source architecture is also being organized so the same core can support other platforms rather than creating separate products from scratch.

Get started

Clone the project and run the core locally.

The exact setup can evolve during alpha development, so check the repository README for the latest prerequisites and installer guidance.

Windows PowerShell
PS> git clone https://github.com/DMTarmeyDev/Agape.git
PS> cd Agape\core
PS> py app.py

Security note: keep API keys and other secrets outside version control. Review configuration files before publishing or sharing a fork.
