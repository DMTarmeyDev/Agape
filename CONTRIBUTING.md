# Contributing to Agape

Thanks for helping improve Agape.

## Before you start

- Search existing Issues and Discussions before opening a duplicate.
- Use Discussions for questions, ideas, and broad design conversations.
- Use Issues for reproducible bugs and clearly scoped feature work.
- Never post API keys, passwords, tokens, personal data, or security vulnerabilities in a public issue.

## Development workflow

1. Fork or branch from the latest `main`.
2. Keep changes focused and easy to review.
3. Add or update tests where practical.
4. Run the repository checks locally before opening a pull request.
5. Explain what changed, why it changed, and how it was tested.

## Pull requests

A good pull request should include:

- the problem being solved;
- the user-visible effect;
- testing performed;
- screenshots for UI changes when helpful;
- any known limitations or follow-up work.

Small, reviewable pull requests are preferred over large unrelated bundles.

## Security

Please follow `SECURITY.md` for vulnerability reporting. Do not disclose exploitable security problems in public Issues or Discussions.

## Project direction

Agape prioritizes a human-first interface, safe automation, model/provider flexibility, repeatable testing, checkpoints, and rollback. Contributions should avoid forcing ordinary users to understand internal models, agents, databases, or terminal details unless they deliberately open advanced controls.
